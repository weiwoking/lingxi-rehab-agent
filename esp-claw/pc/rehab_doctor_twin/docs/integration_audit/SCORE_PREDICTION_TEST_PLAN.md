# 评分预测人工验证计划

本轮未执行以下步骤。用户完成源码检查后可自行验证。

## 静态检查

1. 确认导航顺序为训练报告、评分预测、医嘱管理。
2. 确认仅能选择 `drink_water_right` 与 `pick_book_right`。
3. 确认前端没有写死 55.84 或其他预测分数。
4. 确认后端不调用评分服务接口，不写 session/report/CSV。
5. 确认 `SESSION_DEMO_*`、非 device、invalid、无正式 final score 的记录均被排除。

## 无样本

1. 保持正式历史目录没有合格文件对。
2. 启动用户认可的正式环境。
3. 分别请求两个 task id。
4. 确认均返回 `available=false`、`reason=no_valid_formal_scores`，且不返回默认分数。
5. 确认页面显示暂无可用预测和真实性边界。

## 数量分支

使用经用户确认、由正式设备链产生并已持久化的报告验证：

1. 同任务 1 条：基础分等于该分数、趋势为 0、区间半宽 8、五个未来点相同。
2. 同任务 2 条：核对 0.65/0.35 权重、趋势限制与区间半宽 6。
3. 同任务至少 3 条：只使用最近三条，核对 0.50/0.30/0.20 权重、样本标准差区间。
4. 同任务 0 条但存在其他任务：确认 `basis_type=cross_task`、置信度低、区间额外扩大 2，且没有任务加减分。
5. 刷新页面多次，确认相同输入返回相同结果。

## 边界

分别核对 0、100、NaN、Infinity、布尔值、缺字段、越界分数、来源不明、无 score version、无 `raw_source=real`、session/report 标识不一致等情况。确认所有返回分数与区间均限制在 0 至 100。

## 页面

检查桌面与窄屏布局、任务切换、预测分数、区间、置信度、样本计数、基础分、趋势修正、来源表、未来五次曲线和免责声明。页面不得把预测结果表述为正式评分。
