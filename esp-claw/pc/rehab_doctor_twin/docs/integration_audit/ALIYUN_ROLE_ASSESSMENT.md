# Aliyun Role Assessment

审计时间：2026-07-23

## 是否应接入阿里云

建议把阿里云定位为“可选外部能力层”，不要放进本地康复闭环的必经路径。原因：

1. 当前 ESP -> PC 视觉/评分 -> SD 持久化的核心链路已经按局域网设计，并且有严格 frozen contract。
2. 医生端当前是本机 demo gateway，后续真实 Adapter 更适合先接本地 ESP/PC 服务，确保比赛现场无公网也能运行。
3. 阿里云可用于 LLM、远程留档、远程医生同步或赛后云端分析，但不应阻塞本地训练开始、停止、评分查询和追人安全控制。

## 推荐职责

| 职责 | 建议 | 理由 |
| --- | --- | --- |
| LLM 对话/工具调用 | 可继续使用 ESP-Claw 通用 LLM backend/DashScope 配置 | 已有配置能力，和康复数据合同解耦 |
| 远程归档 | 后续可做异步上传 `score_result.json`、报告摘要、脱敏日志 | 不影响本地闭环；失败可重试 |
| 医生远程查看 | 可选，放在 PC Gateway 之后 | 避免 P4 直接暴露公网 |
| 评分计算 | 不建议当前迁到云 | 评分服务已有本地 Python/DTW/模板依赖和冻结 job API |
| 实时车控/追人 | 不应接云 | 延迟和可用性风险高，安全控制必须本地闭环 |
| 患者隐私数据存储 | 需要专门合规设计后再做 | 当前没有鉴权、脱敏、审计、数据授权设计 |

## 集成顺序建议

1. 先完成本地 Adapter：P4/ESP 状态和 PC 评分结果转换为医生端现有 `/ws/live` 协议。
2. 再做只读云归档：从 PC Gateway 或后台 worker 上传结果摘要，不改变 ESP/评分服务合同。
3. 最后再考虑云端多端同步和远程医生端，需要鉴权、患者授权、脱敏策略和断网降级。

## 零回归底线

阿里云接入不能修改以下接口语义：ESP capability 输入输出、评分 job API、`rehab_score_result_v1` 字段、医生端 WebSocket 消息类型、`ROM_score` 大小写、person-follow 安全边界。云侧失败时，本地训练和评分查询应仍能按当前设计运行。
